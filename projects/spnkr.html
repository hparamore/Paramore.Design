SPNKr

Role Solo, Design & Build
Discipline Product Design · Art Direction · Frontend
Stack Node · Socket.IO · SQLite · Vanilla JS
Status Running in production, at home

The actual thing, on the actual machine. Eight game servers where I used to be able to afford two.

01 // The bill

I was renting two servers and wanting a third.

For a couple of years I paid a hosting company about $30 a month to run two dedicated game servers. That money bought exactly two games. Wanting a third meant paying for a third, or tearing one down and losing the world in it.

The rented boxes were also mediocre, and closed. Underpowered hardware on someone else’s network, behind a panel I couldn’t change. Adding a mod, editing a config, pulling a save down to look at it, all of it went through whatever the panel felt like exposing.

Meanwhile a perfectly good computer sat in the next room doing nothing. Better CPU, better internet, and every file on it mine to touch.

$0 Monthly hosting, down from about $30
8 Game servers configured, up from two
100% File access, for mods, configs and saves

The marginal cost of one more game went to zero. So we started adding games.

Roughly $360 a year saved, against the electricity of a machine already plugged in. But the savings aren’t what changed how we play. We now run things nobody would have paid fifteen dollars a month to try.

02 // Version one

It worked. That was the whole brief.

Start, stop, restart. Player counts. Scheduled restarts. Automatic backups. Crash detection that brings a server back on its own. Discord commands so friends could start a server without me being home, or awake.

All of it worked. I used it daily for four months. It looked like this:

Version one. Functional, and completely anonymous.

Indigo on blue-black. Soft shadows, sixteen-pixel corners, four stacked config rows per card each opening its own modal, and two animations that pulsed forever. It’s the exact interface you get when nothing is decided and everything is generated, which is what happened. I was solving the hosting problem and letting defaults land.

03 // Four months of using it

Living with a tool tells you what a mockup won’t.

I never read most of the card. Eleven data points at the same size, and I only ever wanted three: is it up, is anyone on it, what’s the address. The backup retention count is something I set once a year, and it was taking up half the card.

There was no stop button. The only way to shut a server down was a toggle labelled for what happens on boot. I knew because I wrote it. Nobody else did.

It lives on a second monitor. Two infinite pulse animations weren’t a nice touch, they were something twitching in my peripheral vision for hours.

Four modals for one task. Setting up a server meant opening Schedule, closing it, opening Backups, closing it, opening Idle.

04 // Why redo it

It worked for me. That’s a low bar.

Building it took a long stretch of decisions in code, and once it was working I just used it. Four months of dogfooding later, it had earned a real pass, and I wanted to put it on GitHub so other people could stop paying rent too.

That second goal changed the brief completely. A tool only I use can assume I know things. A tool anyone can set up cannot.

Open sourcing it meant designing for someone who has never seen it.

The hardest part of self-hosting isn’t the software, it’s port forwarding — every router calls it something different, buries it somewhere different, and gets it wrong silently. I’d needed help with it myself. So the redesign added real helper content: instructions written to work on any router, my machine’s actual internal IP filled in, and a flag on the card until it’s done.

The same thinking covered the rest of setup. Installing dedicated servers and registering Windows services is genuinely tedious, and it’s exactly what a coding agent is good at, so the app ships prompts ready to copy, written with the constraints that actually trip agents up. Then it all had to be tested properly — every screen size, empty states, a dropped connection, servers that report nothing.

05 // The name

Everything in my house is named after Halo.

My phone is 343 Guilty Spark. My watch is Cortana. The AirPods are Truth and Reconciliation, the headset is Regret. Computers two and three are Scorpion and Wraith. The TVs are Arbiter and Spartan.

So the new machine needed a name, and I’d used most of the good ships and characters. The rocket launcher came up. SPNKr.

Naming it was the first design decision, and it made every other one easier.

The M41 is two tubes and a handle. Stubby, mechanical, unglamorous — equipment, not decoration. Once that was the target, the visual questions mostly answered themselves. Warm gunmetal instead of consumer blue-black. Two-pixel corners instead of sixteen. Borders doing the work instead of shadows. And one rule I wrote down before touching any markup, because the thing lives on a second monitor:

Anything that moves while nothing has changed is a defect.

That killed both pulse animations, made motion a signal rather than decoration, and later made me delete a scrolling ticker I’d already built and liked.

06 // Working out the mark

Most of it was deciding what it wasn’t.

Before the mark, the direction. I tried a few and rejected them for specific reasons. A clean ops-console look, Grafana-ish, was the safest and the most anonymous — the thing I was trying to get away from. Arcade CRT with scanlines and glow had the most personality but fought legibility on a dashboard you glance at to see if something is down. Swiss-industrial signage was close, but read as a poster, not as kit.

What stuck was a field terminal. Issued, legible, unfussy.

Working the mark out on paper.

My first mark was two circles side by side, and it was wrong because I’d drawn it from the name instead of the object. At sixteen pixels it read as “oo”. Glasses. Infinity symbol.

Going back to an actual reference fixed it. The bores sit offset diagonally, inside a rounded housing — and that asymmetry is the whole identity. A symmetric pair reads as goggles no matter how you draw it.

Then I tested four versions at every size they’d actually appear. Thin outlined rings collapsed into mush below 24px. A capsule housing read as a map pin. A literal version with the receiver block drawn in turned to sludge under 32px. The one that survived was the simplest: bores knocked out of a solid housing, because a positive shape holds at sixteen pixels where an outline doesn’t.

If it only works at 96 pixels, it isn’t the mark yet.

Then it earned its keep. The mark’s geometry recurs as the status readout on every card, two bars staggered to echo the bores. I tried stamping the actual logo on each card first — it read as branding, not instrumentation, and made the header mark feel cheaper by repetition. The abstraction was better.

The last piece was making the spec enforceable. A checklist you’re supposed to remember is a checklist nobody remembers, so a script now checks sixteen rules against the code: no shadows, no looping motion, corner cap, three semantic colors, every text color measured for contrast. Exceptions have to be declared inline with a written reason, and get reprinted on every run so they stay visible.

07 // The difference

Same servers. Same data. Same viewport.

The rule that shaped the card: the card shows state, the panel owns settings. A chip only appears when something needs doing, and clicking it opens the panel scrolled to the fix.

08 // Details

Four modals became one panel.

Everything for one server, in one place.

The step that trips everyone up, with real instructions and my actual internal IP filled in.

Installing servers and registering Windows services, handed to an agent with prompts ready to copy.

The one place motion is allowed. It stops the moment the server settles.

09 // In use

Mostly read from a phone.

10 // Where it stands

Running, at home, right now.

Eight games on the spare machine, controlled from a browser or from Discord, and nobody pays a hosting company anything. It’s on GitHub so anyone can do the same.

The design pass also turned up a pile of engineering, because redesigning something means reading every file. The repository couldn’t start from a clean clone. An apostrophe in a server password broke the copy button. The card grid was being destroyed and rebuilt four times a minute. And the player-count fallback reported “unknown” as “zero” — which mattered, because the auto-shutdown feature turns off servers it believes are empty.

The design pass found the bugs. You have to read everything to redesign it.
