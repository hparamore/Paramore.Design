Set up Claude like I do

Last time I showed you how I paint. This is the paint and the brushes: the setup behind everything I demoed, in the order I’d do it.

You need: a paid Claude plan (Pro or above) for Claude CodeThe Claude desktop app (claude.com/download)Figma, for the Figma part

01 Claude Code: Claude that can touch your files

Regular Claude chats with you. Claude Code works inside a folder on your computer: it reads your files, edits them, runs commands and builds things. Most of what I showed you happened here.

Start it. Easiest: open the desktop app and click the Code tab. Or in Terminal:

curl -fsSL https://claude.ai/install.sh | bash cd ~/Documents/my-project claude

Folders. Claude works in the folder you open it in, and nothing outside it unless you add more: + › Add folder in the app, or /add-dir.

Permissions. It asks before it acts. Shift+Tab switches modes: ask every time, auto-accept edits, or Plan (it proposes and changes nothing). Start in Plan.

CLAUDE.md is the most important file you’ll write. It’s plain-text instructions Claude reads at the start of every session. Put yours at ~/.claude/CLAUDE.md for every project (who you are, how you like to work), and a CLAUDE.md in each project folder for that project’s rules. Run /init to have Claude draft one.

02 Connect Figma

Figma’s MCP server is a plug that lets Claude see your Figma files: the selected frame, its layout, variables, components and a screenshot. You can point at a frame and say “build this,” or have it check that the code matches the design. The online version can also create and edit layers in Figma.

Easiest (Claude Code): install Figma’s plugin, which adds the server and Figma’s own skills. Then run /mcp and sign in to Figma.

claude plugin install figma@claude-plugins-official

From the Figma desktop app: open a file, press Shift+D for Dev Mode, then click Enable desktop MCP server in the right panel (read-only, needs a paid Dev or Full seat).

claude mcp add --transport http figma-desktop http://127.0.0.1:3845/mcp

Try: select a frame in Figma, then ask “Build the frame I have selected in Figma as a web page, and use my colors as variables.”

03 Claude Design

Claude Design is Anthropic’s tool for visual work: describe a page, deck or design and it makes a first version you can edit by chatting, commenting or changing it directly. It can read your code or design files to match your colors, type and components. I use it for fast first versions, then make them look less like Claude made them in twenty minutes. Finished designs export to PDF, PowerPoint or HTML, or go to Claude Code to be built for real. Find it at claude.com/product/design; what your plan includes may change.

04 Skills: teach Claude your process once

A skill is a folder holding a SKILL.md file: a name, a one-line description of when to use it, and the instructions. Claude reads the description and uses the skill when your request matches, or you call it by name with /skill-name.

Install other people’s skills. Type /plugin in Claude Code to browse and install plugins, which bundle skills. Or drop a skill folder into ~/.claude/skills/.

--- name: art-direction description: Set a deliberate visual direction before building any UI. Use when starting a page, or when it looks AI-generated. --- 1. Ask for 2–4 reference screenshots…

Make your own. Notice something you explain to Claude over and over. Write the steps down the way you’d teach a junior designer, including the mistakes to avoid. Save it as a skill, use it on a real project, then fix it where it went wrong. The official skill-creator plugin will interview you and write it for you:

/plugin install skill-creator@claude-plugins-official

How I made mine. AI-made UI kept coming out looking the same: centered hero, three cards, soft shadows. So art-direction walks through layout, type, color, finish and motion. For each one, it names the default it would reach for and makes me pick something on purpose, then writes an ART-DIRECTION.md that the build has to follow. /kickoff is the checklist I was repeating at the start of every project: ask the scope, pick the platform, run art direction, check for an existing design system, choose the right tools, then write the project’s CLAUDE.md and a work log. Both started as notes I kept retyping.

05 Tips I use every day

  1. Plan before you prompt. Say who it’s for, what it does and what done looks like. Use Plan mode for anything big.
  2. Ask it to ask you. End with “Ask me anything you’re unsure of before you start.”
  3. Show, don’t describe. Drop in screenshots, a Figma frame or a site you like. One picture beats a paragraph.
  4. Keep a work log. I have Claude update a WORK_STATUS.md after every session, so the next one picks up where it left off.
  5. Make it check its own work. “Open it in the browser, take a screenshot, fix anything off.” Then look yourself.
  6. Get a second opinion. Have a fresh session, or a different AI, review the work for bugs and security problems.
  7. Save often with Git. Ask Claude to commit after each working step, so any mistake is one undo away.
  8. Fix the look by hand. Let AI do the first 80%. The last 20%, the part that doesn’t look AI-made, is your job, and it’s why clients pay you.
  9. Start fresh when it gets confused. A long, tangled chat gets worse. Open a new session and point it at your CLAUDE.md and log.
  10. Turn repeats into skills. The third time you explain something, save it as a skill.
